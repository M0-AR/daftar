How it works

The model does not remember your documents. It reads them.

That single design choice is why Daftar can be small, private and honest. Your question is matched to passages first; the model only writes from what was found. If the answer is not in your documents, the citations show it.

Drop in PDFs, DOCX, Markdown, text, HTML, CSV or scans. Organise them into collections — one per client, project or case.

Text is pulled page by page. Scans go through OCR. Headings and tables are kept where possible, so a citation can name the section.

Two indexes live in a local SQLite file: meaning (embeddings) and exact words (keywords). Names, codes and dates are never lost in a vector.

Your question fetches the closest passages. Weak and duplicate matches are dropped before the model sees anything.

The local model writes from those passages only. The answer carries numbered citations and a match score, so you can verify every claim.

Why this matters: a cloud chatbot asked about a private contract has to send the contract to someone else's computer. Daftar sends nothing. It finds the relevant pages on your disk and asks a model on your disk to read them. The citation is not decoration — it is the audit trail.

Who it is for

Built for people who cannot send their documents to the cloud.

Lawyers, accountants, clinicians, researchers, agencies and operations teams all face the same trade-off: useful answers versus confidential files. Daftar removes the trade-off.

Legal & compliance

Ask a contract about renewal, liability or notice periods and get the clause, not a paraphrase.

Finance & operations

Reconcile invoices, find the reason a target was missed, and keep the source line in view.

Healthcare & research

Work through notes and papers on a machine you control, without a data-processing agreement.

Government & NGOs

Keep citizen, grant and case files inside the organisation — including offline at a field office.

Agencies & consultants

Keep every client's documents in a separate collection on your own laptop. No shared cloud tenant.

Solo professionals

One install, no subscription, no per-seat API bill. Runs on a normal laptop with a small model.

Architecture & privacy

Small surface. Clear rules.

Daftar is a local web app: a Python server on loopback, a static interface, and a model engine you choose. There is no cloud account, no analytics script and no third-party font.

Two engines, one app

Use the built-in llama.cpp engine for chat with no extra install, or connect Ollama for chat, embeddings and vision OCR. Any OpenAI-compatible server can be enabled explicitly for advanced setups.

Your data in one folder

Documents, extracted text, the SQLite index and chat history live under ~/.local/share/daftar on Linux, ~/Library/Application Support/Daftar on macOS and %APPDATA%\Daftar on Windows. Delete the folder and everything is gone.

Locked to your machine

The server binds to 127.0.0.1, validates the Host header, requires a custom header on writes and blocks cross-origin preflights. The child engine can run with a random API key. Remote engines are opt-in, never silent.

No telemetry, ever

No analytics, no crash reporting, no remote fonts or scripts. The app works with the network cable unplugged. The only network calls are the ones you configure.

Honest threat model: “local” means your documents are not sent to a cloud service. It does not protect against malware, a compromised operating-system account, or someone who can read your disk. Use full-disk encryption and normal access controls for that layer.
Get started

Three commands to a private document chat.

Python 3.11+ and about 2 GB of free disk for a small model. No account, no API key, no cloud sign-up. The built-in engine handles chat; add Ollama if you want vision OCR for scans.

Terminal
# 1. get the code
git clone https://github.com/M0-AR/daftar.git
cd daftar

# 2. install into a virtual environment
python -m venv .venv
# Windows: .venv\Scripts\activate
# macOS / Linux:
source .venv/bin/activate
pip install -e .

# 3. run
daftar
Optional: scans and embeddings via Ollama
ollama pull nomic-embed-text
ollama pull qwen3.5:2b
# then choose Ollama in Settings → Engine
# and pick a vision model for scanned PDFs

Your first five minutes

  1. The window opens by itself. If you started it headless, open the address it printed.
  2. Create a collection, for example Supplier contracts.
  3. Drop in two or three documents you already know well.
  4. Ask a question whose answer you can verify by eye.
  5. Click the citation and compare it with the source passage.

Questions, answered plainly

Everything a beginner asks.

If your question is not here, the beginner guide in the repository walks through the whole app without jargon.

Is my data really private?

Yes, in the sense that matters: your documents are read and indexed on your computer, and the model runs on your computer. Daftar does not create an account, does not send telemetry and does not call a cloud API unless you explicitly configure a remote engine. The honest limit: local software cannot protect you from malware or from someone with access to your operating-system account.

Does it need the internet?

Only to download the app and a model the first time. After that, the app, the index and the model work offline. The interface loads no remote fonts, scripts or images.

Which files can I add?

PDF, DOCX, Markdown, plain text, HTML and CSV. Scanned PDFs need OCR: choose Ollama with a vision model such as PaddleOCR-VL. The built-in engine is chat-only, so it will tell you when a scan has no extractable text instead of pretending.

Do I need a GPU?

No. A 2-billion-parameter model runs on a normal CPU and is fine for document questions. A GPU makes answers much faster; the warm latency figure on this page was measured on an RTX 3090.

Does it work with Arabic?

Yes. Arabic text is normalised for search, Arabic documents are indexed, and you can ask questions in Arabic. The interface is in English. Mixed Arabic/English documents work, and the invoice in the demo includes an Arabic note you can ask about.

How is it different from a cloud chatbot?

A cloud chatbot is a general assistant that may or may not have your documents. Daftar is a retrieval system first: it finds the exact passages in your files, then a local model writes from them. The difference is privacy plus verifiability — every claim has a source you can open.

What does the match score mean?

It is a relevance indicator for the retrieved passage, not a probability that the answer is true. Use it to compare sources, then read the citation. In the desktop app the score comes from the hybrid retrieval and reranking stage.

Can I delete everything?

Yes. Delete a collection or document in the interface, or remove the data folder (~/.local/share/daftar, ~/Library/Application Support/Daftar or %APPDATA%\Daftar, or the path in DAFTAR_HOME) to erase the index, extracted text, chat history and settings. Original files you added from elsewhere are not touched unless you copied them into the data folder.

Is it free? Can I use it at work?

Daftar is open source under the MIT licence. You can use it commercially, modify it and redistribute it, provided you keep the copyright notice. There is no per-seat fee and no token bill.

Can I use my own model?

Yes. Add any GGUF chat model to the built-in engine, or point Daftar at an Ollama or OpenAI-compatible server. Embeddings and OCR still need a provider that supports them; the app tells you what is missing instead of failing silently.

Why does the built-in engine not do everything?

It is deliberately small: one process, chat only, no extra install. Embeddings and vision OCR need additional model files, so they are handled through Ollama or another compatible provider. The app reports the exact capability gap rather than degrading quietly.

How do I publish this site?

The site is the docs/ folder. Push the repository to GitHub, open Settings → Pages, choose “Deploy from a branch”, select main and /docs, and save. GitHub serves docs/index.html at https://M0-AR.github.io/daftar/. The .nojekyll file is already there.
